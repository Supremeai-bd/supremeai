# Core SSE: ব্যর্থতা ও memory boundary

এই branch-এর পরিবর্তন deploy বা security approval নয়। প্রাথমিক `GET/POST /api/v1/stream/chat`-এ `core/api/routes/stream_chat_sse.py` ব্যবহৃত হয়। একই ফাইল legacy `/api/chat/stream`-ও ঘোষণা করে, কিন্তু বর্তমান `core.app` mount order-এ `core/api/routes/task.py`-এর আলাদা handler আগে মেলে; route-shadow অবশিষ্ট আছে, পরিবর্তন করা হয়নি।

- `stream_chat_sse.py`-এ কোনো token পাঠানোর আগে stream ব্যর্থ/খালি হলে non-stream fallback হতে পারে। Partial token পাঠানোর পরে stream ব্যর্থ হলে দ্বিতীয় উত্তর জুড়ে দেওয়া হয় না: `error` event দিয়ে stream শেষ হয়; `done` বা `[DONE]` দেওয়া হয় না। Fallback ব্যর্থ বা খালি হলেও `error`, সফল completion নয়।
- `task.py`-এর legacy handler-এও stream ব্যর্থ বা খালি হলে `error` event, সফল `[DONE]` নয়। `ModelRouter.async_route_and_stream` partial token-এর পরে fallback যোগ করে না; প্রথম token-এর আগে fallback এখনও সম্ভব। অন্য streaming route ও বাস্তব frontend এই error-event ঠিকমতো দেখায় কি না প্রমাণিত নয়।
- `HoneypotMiddleware` inspected request body replay করার পরে কৃত্রিম `http.disconnect` না পাঠিয়ে আসল receive channel অনুসরণ করে; এতে response সম্পূর্ণ হওয়ার আগেই stream কাটা যায় না। Request-body read ব্যর্থ হলে downstream-এ partial/uninspected request না পাঠিয়ে 400 ফেরত দেওয়া হয়। এটি attack signature বদলায় না। অতিরিক্ত বড় body-এর বিদ্যমান inspection-skip policy আলাদা review প্রয়োজন।
- `stream_chat_sse.py`-এ আগের `AutoRAGInjector` memory recall ও session exchange write বন্ধ। ব্যক্তিগত consent, প্রত্যাহার ও deletion-এর সঙ্গে এ route-এর ঐক্যবদ্ধ enforceable সংযোগ ছিল না। ফলে এখানে **সম্মতি থাকলেও** legacy recall/write হয় না; সম্মতিসাপেক্ষ memory পুনরায় চালু করতে authenticated per-user consent, storage scope, revocation/deletion, injection resistance ও review দরকার। পুরোনো Supabase/vector data বা backup এই পরিবর্তন মুছে দেয় না। অন্য API এবং `AutoRAGInjector`-এর অন্য সম্ভাব্য caller/store আলাদাভাবে audit প্রয়োজন; gateway-র local consent prototype সব route-এর সমাধান নয়।
- Provider-এ পাঠানো request বা আগের data প্রত্যাহার করা যায় না। প্রথম token-এর আগে fallback দ্বিতীয় inference call করতে পারে; provider/free-tier limit ও $0 বাস্তব খরচ যাচাই হয়নি। High-risk privacy ও response-contract পরিবর্তনের জন্য human review, অনুমোদিত staging-এ client compatibility ও rollback plan প্রয়োজন; production security/load পরীক্ষা নয়।

Local tests-এ mocked provider, FinOps/revocation dependency ও বাস্তব স্বাক্ষরিত test JWT সহ `core.app` middleware chain এবং দুই effective route পরীক্ষা করা হয়েছে; এগুলো deployed environment, বাস্তব provider, Redis revocation, production cost বা security certification প্রমাণ করে না। পূর্বে `gateway/tests/test_stream_chat_contract.py` এবং `test_task_endpoints.py` invalid fake bearer নিয়ে 401 পেত; টেস্টে test-only signed JWT ব্যবহার করা হয়েছে, authentication bypass বা production auth দুর্বল করা হয়নি। আলাদা `gateway/tests/test_hitl_route_ownership.py` shadow-গণনা failure `origin/main`-এও পুনরুৎপাদিত; alias collision অমীমাংসিত।
